# 路线图

> 状态：已评审 · 最后更新：2026-09-12

里程碑按依赖关系排序，不按日历排期。每个里程碑列出范围与验收标准；验收全部通过才进入下一个。域文档中的「规划 · Mx」与本文件对齐。

## M0 脚手架（当前）

**目标**：三层骨架就位，协议打通最小闭环。

范围：
- 仓库结构、文档集、开发规范、CI 骨架
- 前端：Vite + React 19 + Tailwind 4 + `src/ui` 种子 + 自绘顶栏 + 开始页（预设 / 勾选 / 试一次）+ 编排页演示画布 + 设置分段（外观 / 行为 / 快捷键 / 调试 / 关于）+ 自研 i18n
- 引擎：JSON-RPC stdio 服务、`engine.hello` / `engine.ping` / `engine.shutdown`、`flow.validate` / `flow.start` / `flow.cancel`、节点注册表骨架、mock driver 骨架、pytest 通过
- 壳：Tauri 2 无边框窗口、sidecar spawn、偏好落盘、关闭行为、Windows 开机自启、更新检查占位、上述方法往返
- schemas 真源 + codegen 脚本 + 版本同步脚本

验收：
- `pnpm dev` 起前端，`pnpm tauri dev` 起完整应用
- 开始页可「试一次」，状态栏用人话显示就绪 / 忙碌
- `pytest`、`vitest`、`cargo check` 全绿

## M1 引擎核心

**目标**：不依赖真实桌面，用 mock driver 跑通完整执行语义。

范围：节点协议与注册表完整实现、执行器（拓扑调度/状态机/协作式取消/双层超时）、三层作用域、模板插值、dry-run、SQLite 执行历史、核心节点首批（flow 控制 + 数据 + fs + core.log）、协议 golden tests、覆盖率 ≥80%。

验收：
- 示例流程（含分支/循环/变量/取消/超时）在 mock driver 上执行轨迹符合断言
- `flow.validate` 对非法流程给出结构化 issues
- 取消与超时路径有专项测试

## M2 编辑器

**目标**：用户能从开始页进入编排，用预设积木搭出合法流程并保存；编完与预设走同一执行语义。

范围：React Flow 画布（拖拽/连线/撤销重做/对齐）、积木面板（按「我想做什么」分组，映射引擎注册表；按键积木先选方案再列出该方案映射表供点选，像选宏）、属性表单（RHF+Zod，必填先行）、实时校验反馈上图、`*.flow.json` 新建/打开/保存/另存、开始页勾选与流程文件同步、迁移 UI、命令面板接入编辑器命令。

验收：
- 纯手工操作搭出 M1 的示例流程并保存；重开文件内容一致
- 从未使用过的用户能从「开始」点「自己改步骤」进入编排，用预设积木改一处后保存，「试一次」执行轨迹与画布一致，无需阅读 PROTOCOL
- 校验 issue 在画布步骤上可见可定位，文案写明缺了什么、点哪里补
- 撤销/重做覆盖全部画布操作

## M3 执行体验

**目标**：运行一个流程的过程完全可观测、可控制。

范围：执行控制条（运行/暂停/继续/取消/dry-run）、画布执行高亮、日志面板（traceId 聚合、级别过滤）、历史列表与详情页、失败定位到节点、执行前预演对比。

验收：
- 从点击运行到看到结果，每一步状态与日志实时可见
- 失败执行可从历史详情一键跳回画布失败节点
- dry-run 轨迹与真实运行轨迹结构一致

## M4 平台 driver

**目标**：真实桌面自动化，Windows 先行。

范围：pywinauto driver 完整能力（窗口/元素/键鼠/剪贴板/进程）、macOS pyobjc 能力子集 + 授权引导、Linux pyatspi 能力子集、元素定位器编辑器（选择器测试器）、凭据节点接通 keyring。

验收：
- Windows 上真实跑通"打开记事本 → 输入 → 保存"端到端
- 三平台 driver 能力矩阵文档化，缺失能力有明确错误码
- 凭据全流程不出明文

## M5 打磨与发布

**目标**：可分发的正式版本。

范围：信任分级与危险操作确认、自动更新（签名通道接通）、打包流水线（msi/dmg/AppImage）、凭据管理页、性能达标（PRODUCT.md §6）、SBOM、崩溃上报（本地日志打包导出，无遥测）。设置外观/行为/调试已在 M0 落地。

验收：
- 三平台安装包构建并通过冒烟
- 未信任流程的完整拦截路径有 e2e 测试
- 更新通道在测试环境验证
