# ADR-0007：集中式命令注册表

- 状态：已接受
- 日期：2026-09-11

## 背景

应用内动作（运行流程、保存、打开历史…）有多个触发入口：按钮、菜单、快捷键、命令面板。若每个入口各自实现动作逻辑，行为必然分叉（快捷键能触发被禁用按钮的动作等）。

## 决策

建立集中式命令注册表：每个命令声明 `id / title / scope / shortcut / when / run`。命令面板、菜单、快捷键、按钮**都只是触发器**，共享注册表中的唯一实现。`when` 子句决定命令在何时可用，所有入口的可用态由它统一推导。

## 理由

- 行为一致性：任何入口触发的都是同一份实现、同一套可用性判断。
- 可测试：`when`/`run` 注入显式上下文，不读全局单例，纯函数式测试。
- 快捷键冲突在注册期可检测（dev 下 throw），而不是运行期玄学。
- 命令面板免费获得全部命令的搜索与呈现。

## 后果

- 所有动作必须建模为命令，包括"一次性"的 → 接受，一致性收益大于样板成本。
- 上下文对象需要维护（编辑器状态、引擎状态等）→ 定义在 `lib/commands/context.ts`，随模块演进。

## 备选（已否决）

- **各入口自实现**：行为分叉、快捷键与按钮状态不一致，已被无数桌面应用验证为坏味道。
- **事件总线**：动作无声明式元数据（标题/快捷键/可用性），命令面板无从索引。
