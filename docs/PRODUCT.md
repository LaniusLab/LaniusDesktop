# Lanius Desktop 产品规划

> 状态：已评审 · 最后更新：2026-09-12
> 实现进度：产品目标态；当前代码里程碑见 [ROADMAP.md](ROADMAP.md)（**M0**）。

## 1. 愿景与定位

**Lanius Desktop 是本地优先的跨平台桌面自动化工作台。** 用户把重复的桌面操作（点击、填表、跨应用搬运数据、定时巡检）做成可一键开跑的作业，必要时再改步骤；Python 引擎执行，每次执行可追溯、可回放、可审计。

默认路径：**选预设 → 勾选步骤 → 试一次**。流程文件是用户资产：编排是一等入口，用预设按键与操作积木改完即可运行。

一句话：**先把重复的事做成一键，再按需把作业单维护成可版本化的自动化资产。**

## 2. 目标用户

1. **日常桌面用户（主）**：会用电脑，每天在多个软件间重复操作，不愿写脚本，也不想先学节点类型 / JSON / 协议。
2. **小型团队运营/测试**：把人工操作固化下来共享，流程文件能进 Git、能 review。
3. **开发者**：把 Lanius 当作桌面自动化运行时，用 Python 写自定义节点扩展能力。

明确不服务：需要云端协同编排的企业 IT（本产品无服务端）。V1 不做「一键录制即成流程」（录制器见 ROADMAP 里程碑之外），但默认不要求理解节点类型、JSON 或协议。

## 3. 核心场景

### 3.1 开跑——开始页

打开应用先到开始页：选一套预设作业、勾选要做的步骤、按「试一次」。执行状态用人话（就绪 / 正在运行 / 完成）。要改步骤时点「自己改步骤」。

界面不展示 `window.find`、`traceId`、`dry-run` 等术语；这些只出现在「技术详情」或排障入口。预演对用户说「先演练、不改电脑」。

### 3.2 编排——脚本入口

编排入口：侧栏「编排」与开始页「自己改步骤」。用户用预设按键与操作积木（按一下键、组合键、输入文字、单击、找到窗口、等一会、记一条日志）搭流程，连线定顺序，保存为 `*.flow.json`。

用户改过的流程与内置预设走同一执行语义。

流程实时校验（缺必填、悬空步骤、类型不匹配），提示写「缺了什么、点哪里补」。

### 3.3 执行过程

试一次后，控制条显示状态机流转。画布上当前步骤高亮，运行记录用人话展示结果。支持：暂停/继续、取消（协作式）、先演练不改电脑、单步重跑。traceId 用于排障，不常驻主界面。

### 3.4 运行记录

每次执行落库（SQLite）：触发方式、起止时间、最终状态、每个步骤的输入输出摘要、错误码与 traceId。失败执行可一键回到编排页的失败步骤。

### 3.5 凭据与信任

密码类参数只存 keyring 引用（`secret://...`）。打开来路不明的流程按「未信任」处理：禁止自动运行，危险步骤逐一确认。

### 3.6 扩展

开发者在 `engine/src/lanius_engine/nodes/` 下新增节点类，声明 inputs/outputs/config schema，注册即用。自定义节点与内置积木走同一校验与执行路径。

## 4. 功能范围

### V1 范围内

- 开始页：预设场景、步骤勾选、一键试一次
- 可视化编排器（积木/连线/子流程引用/撤销重做），编完即可运行
- 核心积木：流程控制（条件/循环/等待/子流程）、键鼠、窗口管理、文件系统、HTTP、剪贴板、日志
- 执行引擎：状态机、协作式取消、节点级+流程级超时、变量作用域、演练模式
- 运行记录（SQLite）与日志查看
- 全局搜索与应用内快捷键（可改绑定；系统级热键属后续）
- 设置：主题 / 强调色 / 字体 / 动效 / 语言、关闭行为、开机自启、更新检查占位、调试信息与关于
- 凭据管理（keyring）
- Windows 平台 driver 首批完整支持；macOS/Linux driver 为能力子集
- 应用自动更新（签名）

### V1 不做

- 云端同步、账号体系、流程市场
- 录制器（操作录屏生成流程）
- 图像识别节点
- 移动端控制
- 同一全局资源（键鼠）上多执行并行（见 ENGINE.md）

## 5. 设计原则

1. **本地优先**：流程、历史、凭据引用均在本机；无遥测。
2. **文件即资产**：流程是纯文本 JSON；`schemaVersion` + 迁移链保证旧文件可开。用户不必在界面上阅读 JSON。
3. **先开跑后编排**：首页是预设作业台；编排是一等入口。
4. **人话在前**：界面动词用「打开记事本 / 输入文字 / 试一次」；机器 ID 与协议字段只进技术详情。
5. **编完就能跑**：积木改过的流程与内置预设共用同一执行语义。
6. **编排显式可审计**：步骤、顺序与结果写在流程文件和运行记录里，可回放、可 review。
7. **副作用显式**：每个步骤声明 sideEffect；演练模式走完流程且不碰真实桌面。
8. **渐进复杂度**：开始页、积木、表达式、自定义节点共用同一执行语义。
9. **失败要响亮**：错误含 `code` 与下一步建议；排障用 traceId。静默吞错视为 bug。

## 6. 成功度量（内部参考）

- 冷启动到开始页可交互 < 3s（中端硬件）
- 从未用过的人能在约三分钟内按预设试一次并理解下一步
- 引擎 ping P95 < 50ms
- 千节点流程打开/校验 < 1s
- 执行历史万条内查询无感知延迟
- 引擎异常退出由壳捕获并重启；不可丢失流程文件
