# Lanius Desktop 产品规划

> 状态：已评审 · 最后更新：2026-09-11

## 1. 愿景与定位

**Lanius Desktop 是一个本地优先的跨平台桌面自动化平台。** 它让进阶用户把重复性的桌面操作（点击、填表、跨应用搬运数据、定时巡检）编排成可视化的流程文件，由内置 Python 引擎稳定执行，并且每一次执行都可追溯、可回放、可审计。

定位参照系：

| 产品 | 它们的模式 | Lanius 的差异 |
| --- | --- | --- |
| Power Automate Desktop | 商业闭源、Windows 优先、云端账号体系 | 本地优先、跨平台、开源、文件可版本化 |
| 按键精灵 / AutoHotkey | 脚本即全部，无工程化能力 | 流程文件 + 执行历史 + 类型安全协议 + 测试体系 |
| n8n / Zapier | 面向 SaaS API 编排 | 面向**桌面应用 UI** 编排，控制真实窗口与键鼠 |
| Sikuli / PyAutoGUI 脚本 | 裸脚本，无 UI、无状态管理 | 有工作台 UI、执行状态机、凭据管理、安全分级 |

一句话：**把"写一段自动化脚本"升级为"维护一份自动化资产"。**

## 2. 目标用户

1. **进阶个人用户**：每天重复操作多个桌面软件（导出报表、整理文件、跨应用复制粘贴），会基础逻辑概念但不想维护裸脚本。
2. **小型团队运营/测试**：需要把人工操作流程固化下来共享给同事，要求流程文件能进 Git、能 code review。
3. **开发者**：把 Lanius 当作桌面自动化的运行时，自己写自定义节点（Python）扩展能力。

明确不服务：需要云端协同编排的企业 IT（无服务端组件）、零概念的小白用户（不提供"一键录制即成流程"的魔法，录制器最早 M3 才出现且只是辅助）。

## 3. 核心场景

### 3.1 编排（Build）

用户在画布上拖入节点（打开应用、等待窗口、点击、输入、读取单元格、条件分支、循环），连线定义执行顺序，右侧属性面板配置参数。流程实时校验（缺必填参数、悬空节点、类型不匹配），保存为 `*.flow.json`。

### 3.2 调试与执行（Run）

用户点击运行，执行控制条显示状态机流转（validating → running → done/failed）。画布上当前节点高亮，日志面板按 traceId 输出结构化日志。支持：暂停/继续、取消（协作式，节点在安全点退出）、dry-run（只走流程不触发副作用）、单节点重跑。

### 3.3 历史与审计（Audit）

每次执行落库（SQLite）：触发方式、开始结束时间、最终状态、每个节点的输入输出摘要、错误码与 traceId。失败执行可一键定位到失败节点并查看当时上下文。

### 3.4 凭据与信任（Trust）

流程里引用密码类参数时，只存 keyring 引用（`secret://...`），真实值在系统钥匙串。打开来路不明的流程文件时按"未信任"处理：禁止自动运行，危险节点逐一确认。

### 3.5 扩展（Extend）

开发者在 `engine/src/lanius_engine/nodes/` 下新增节点类，声明 inputs/outputs/config schema，注册即用。自定义节点与内置节点走完全相同的校验与执行路径。

## 4. 功能范围

### V1 范围内

- 可视化画布编辑器（节点/连线/子流程引用/撤销重做）
- 核心节点库：流程控制（条件/循环/等待/子流程）、键鼠、窗口管理、文件系统、HTTP、剪贴板、日志
- 执行引擎：状态机、协作式取消、节点级+流程级超时、变量作用域、dry-run
- 执行历史（SQLite）与日志查看
- 命令面板与全局快捷键
- 凭据管理（keyring）
- Windows 平台 driver（pywinauto）首批完整支持；macOS/Linux driver 可用但能力子集
- 应用自动更新（签名）

### 明确非目标（V1 不做）

- 云端同步 / 账号体系 / 流程市场
- 录制器（"录屏生成流程"）——M3 后单独立项评估
- 图像识别节点（Sikuli 式）——依赖重，V1 后用插件形式评估
- 移动端控制（ADB 等）
- 多引擎并行执行同一全局资源（键鼠全局互斥是设计约束，见 ENGINE.md）

## 5. 设计原则

1. **本地优先**：所有数据（流程、历史、凭据引用）在本机；没有遥测上报。
2. **文件即资产**：流程是纯文本 JSON，能进 Git、能 diff、能 review；schemaVersion + 迁移链保证旧文件永续可开。
3. **可审计优于可智能**：宁可要确定性强的显式编排，也不要"AI 猜你想点什么"。
4. **副作用显式化**：每个节点声明 sideEffect；dry-run 必须能完整走一遍流程而不碰真实世界。
5. **渐进复杂度**：画布给普通用户，表达式给进阶用户，自定义节点给开发者——三层能力共用同一执行语义。
6. **失败要响亮**：任何失败都有错误码、traceId、用户可读的下一步建议；静默吞错视为 bug。

## 6. 成功度量（内部参考）

- 冷启动到画布可交互 < 3s（中端硬件）
- 引擎往返延迟（ping）P95 < 50ms
- 千节点流程文件打开/校验 < 1s
- 执行历史万条内查询无感知延迟
- 崩溃率：引擎进程异常退出需被壳捕获并自动重启，用户可感知失败但不可丢失流程数据
